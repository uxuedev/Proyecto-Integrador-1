Diagrama de clases UML

Cada clase corresponde a una colección de Firestore (los atributos son los campos guardados) y sus métodos son las operaciones que ofrece la interfaz. Notificación y Reporte no se guardan: se calculan a partir de las demás colecciones. 

classDiagram
    direction TB

    class Rol {
        <<enumeration>>
        admin
        tecnico
        usuario
    }

    class Usuario {
        +String id
        +String nombre
        +String email
        +Rol rol
        +iniciarSesion(email, contraseña)
        +cerrarSesion()
        +puede(permiso) bool
        +cambiarRol(rol)
    }

    class Equipo {
        +String id
        +String nombre
        +String serie
        +String tipo
        +String estado
        +String falla
        +String diagnostico
        +agregar()
        +editar()
        +eliminar()
        +filtrar(texto, tipo, estado)
    }

    class Cita {
        +String id
        +Date fecha
        +String equipo_id
        +String equipo_nombre
        +String estado
        +agendar()
        +editar()
        +eliminar()
    }

    class MantenimientoPreventivo {
        +String id
        +Date fecha
        +String equipo_id
        +String equipo_nombre
        +String estado
        +programar()
        +editar()
        +eliminar()
    }

    class Historial {
        +String id
        +String equipo
        +String tipo
        +String falla
        +String diagnostico
        +Date fecha
        +registrar()
        +filtrar(desde, hasta, tipo, texto)
    }

    class Ticket {
        +String id
        +String titulo
        +String descripcion
        +String prioridad
        +String estado
        +String equipo_id
        +String creado_por_id
        +String tecnico_id
        +Date fecha_creacion
        +Date fecha_cierre
        +String solucion
        +crear()
        +tomar()
        +asignar(tecnico)
        +cerrar(solucion)
        +eliminar()
        +filtrar(texto, estado, prioridad, tecnico)
    }

    class Notificacion {
        <<calculada>>
        +String nivel
        +String texto
        +construir(citas, preventivos, tickets, equipos)
    }

    class Reporte {
        <<calculado>>
        +String tipo
        +generarPDF()
        +generarExcel()
    }

Diagrama de flujo: inicio de sesión por roles

Todas las páginas internas pasan por este control antes de mostrar información. El menú y los botones se ajustan según el rol. 

flowchart TD
    A([Inicio]) --> B[/Ingresa correo y contraseña/]
    B --> C{¿Credenciales válidas
en Firebase Auth?}
    C -- No --> D[Mostrar: Usuario o contraseña incorrectos]
    D --> B
    C -- Sí --> E[Buscar perfil en colección usuarios]
    E --> F{¿Existe el perfil?}
    F -- No --> G[Crear perfil con rol usuario]
    F -- Sí --> H[Leer rol]
    G --> H
    H --> I{¿El rol tiene permiso
para la página?}
    I -- No --> J[Redirigir al Dashboard]
    I -- Sí --> K[Ocultar menús y botones
no permitidos]
    J --> K
    K --> L{Rol}
    L -- Administrador --> M[Acceso total:
usuarios, eliminar, asignar tickets]
    L -- Técnico --> N[Equipos, citas, preventivo,
historial, reportes, atender tickets]
    L -- Usuario --> O[Dashboard, consulta de equipos,
crear y seguir sus tickets]
    M --> P[Dashboard con notificaciones y gráficas]
    N --> P
    O --> P
    P --> Q{¿Cerrar sesión?}
    Q -- Sí --> R([Fin])

Diagrama de flujo: atención de tickets

Ciclo de vida de una incidencia no planificada, desde que se reporta hasta que queda en el historial. 

flowchart TD
    A([Usuario detecta una falla]) --> B[/Reportar falla:
equipo, título, descripción, prioridad/]
    B --> C{¿Equipo y título
completos?}
    C -- No --> B
    C -- Sí --> D[Guardar ticket con estado Abierto]
    D --> E[Notificación en el Dashboard:
ticket sin asignar]
    E --> F{¿Quién lo asigna?}
    F -- Técnico --> G[Técnico toma el ticket]
    F -- Administrador --> H[Admin asigna a un técnico]
    G --> I[Estado: En proceso]
    H --> I
    I --> J[Técnico revisa y repara el equipo]
    J --> K[/Escribe la solución aplicada/]
    K --> L{¿Solución escrita?}
    L -- No --> K
    L -- Sí --> M[Estado: Cerrado
se guarda fecha de cierre]
    M --> N[Se registra en el Historial de mantenimiento]
    N --> O[El usuario ve su ticket cerrado]
    O --> P([Fin])
